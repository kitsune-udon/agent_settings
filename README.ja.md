# agent 指示テンプレート

このリポジトリでは、Codex 向けのグローバルの既定方針と、リポジトリの実行ポリシーを管理します。二つのテンプレートを一つの指示ファイルに連結せず、それぞれの適用範囲に配置します。この README は、ソースリポジトリのセットアップと保守のガイドです。必須の配布物でも、自動的に読み込まれるリポジトリ指示ファイルでもありません。

## ファイル

| 配布元 | 配置先 | 目的 |
| --- | --- | --- |
| [AGENTS.user.ja.md](AGENTS.user.ja.md) | `~/.codex/AGENTS.md` | 再利用できるコミュニケーション、エンジニアリング、安全性、検証の既定方針。 |
| [AGENTS.project.ja.md](AGENTS.project.ja.md) | `<repository>/AGENTS.md` | 実行ポリシーを必須とするリポジトリ指示。 |
| [実行ポリシー](.agent/agent-execution-policy.ja.md) | `<repository>/.agent/agent-execution-policy.ja.md` | 委任、独立レビュー、検証、受入、runtime Goal の詳細な手順。 |

リポジトリのテンプレートは、実行ポリシーの適用条件を要約します。リンク先のポリシーは必須であり、レビュー範囲、reviewer の適格性、省略条件、検証、受入、回復を定めます。詳細な規則はそこに置き、グローバルの既定方針やセットアップ記録に複製しません。

## レビュー要件

| 作業 | 必須の独立レビュー |
| --- | --- |
| 小さな変更やドキュメント変更を含む、実装した変更単位 | plan review と result review。plan review を省略できるのは、ポリシーの低影響の機械的変更の省略条件を満たす場合だけです。result review で適用条件の妥当性を確認します。 |
| 実装を伴わない重要な判断成果 | 一回の decision review。既存のレビューで要件を満たせる場合があります。調査するだけのために plan review は要求しません。 |
| 選択済みの変更単位の却下または延期 | 判断と理由のレビュー。既存のレビューで要件を満たせる場合があります。 |

候補を未選択の状態にしても、明示的な要件を未達にしたままにする、または完了条件を変える判断はレビュー対象から外れません。ポリシーは、これらの判断と、任意の候補の初期選別、中間仮説、低影響で可逆的な助言を区別します。必須レビュー内の指摘は、再帰的なレビュー段階を追加しません。

ポリシーの非実装者であることと作成者に関する制限を満たす、適格な reviewer を使います。reviewer の context と有効な証拠を再利用します。独立性は、すべてのチェックの再実行を要求しません。計画、省略理由、レビュー記録は、既存成果物内で簡潔にまとめられます。

agent の実行指示は、プロダクトのドキュメントと区別するため、`.agent/` に置きます。

## グローバルの既定方針

`AGENTS.user.ja.md` を、Codex home ディレクトリ内に `AGENTS.md` として配置します。既定のディレクトリは `~/.codex` です。`CODEX_HOME` を設定している場合は、そのディレクトリを使います。既存のグローバル指示を置き換える前に、比較して統合します。

個人の言語・コミュニケーション上の希望と、プロジェクト横断のエンジニアリングの既定方針はここに置きます。上位の runtime 指示に従う範囲で、より具体的なリポジトリ、ディレクトリ、タスクの指示が、これらの既定方針を上書きできます。

## リポジトリへの初回導入

必須の独立レビューを意図し、runtime が対応するリポジトリに、実行ポリシーを採用します。これは配置する適用範囲の選択であり、採用したリポジトリ内の特定の変更を除外するものではありません。後からレビューを利用できなくなった場合も、ポリシーの保留要件を適用します。

採用前に、runtime と上位指示が次を許可することを確認します。

- 必要な枠を確保し、ポリシーの非実装者であることと作成者に関する制限を満たす、適格な独立 sub-agent に、変更または判断の必須レビューを割り当てる。
- reviewer が関連ファイル、差分、受入基準、検証の証拠にアクセスできるようにする。
- 該当する実装または受入の段階へ進む前に、レビュー結果を受け取り、指摘に対処する。

sub-agent に対応しているだけで十分だと仮定せず、実際のツール、権限、ライフサイクルの制限を確認します。能力が不確実な場合、必要に応じて、許可された読み取り専用のレビュー試行を行います。利用できない独立 reviewer を自己レビューで置き換えられると仮定して、ポリシーを採用しません。

リポジトリのテンプレートを、リポジトリのルートに `AGENTS.md` としてコピーし、`.agent/agent-execution-policy.ja.md` を参照先のパスに配布します。既存のリポジトリ指示を無条件に置き換えず、統合します。ポリシーのパスを変えた場合、`AGENTS.md` のリンクを更新し、正しく解決できることを確認します。

リポジトリのテンプレートと実行ポリシーは、同じソース commit のものを使います。その commit を既存のセットアップまたは保守記録に残し、後の更新時に、配布した baseline と局所的な追加を区別できるようにします。

テンプレートの一般的な「リポジトリの背景」節は、利用可能な範囲で、確認済みのリポジトリ情報に置き換えます。

- セットアップ要件と、実際の test、lint、型チェック、build コマンド。
- 関連するディレクトリの境界と、既存のアーキテクチャ上の慣例。
- 生成ファイルと、その更新手順。
- 変更時に重要となるドメイン不変条件、互換性の制約、移行、既知の失敗形態。

グローバルの既定方針を各リポジトリへ複製しません。必要に応じて、より狭い範囲の指示を、関連するサブディレクトリの `AGENTS.md` に置きます。採用した実行ポリシーのレビュー要件を維持します。

## 配置済みの指示の更新

1. 配置済みのソース commit と、置き換える commit を特定します。来歴が不明な場合、更新前に配置済みファイルを直接比較し、baseline を確立します。
2. 置き換える commit の `AGENTS.project.ja.md` と `.agent/agent-execution-policy.ja.md` の両方を、配置済みのペアと比較します。リポジトリ固有の追加を上書きせず、保ちつつ整合させます。ペアを一緒に更新します。一方に upstream の変更がない場合も、選んだ baseline に一致することを確認します。
3. 最終差分を確認し、必須のポリシーリンクが正しく解決できることを確認します。影響するレビュー、省略条件、独立性、受入、保留の要件を、階層下の指示や override 指示と整合させます。ポリシーを採用したリポジトリの指示更新も、既存のレビュー方針の対象です。agent の義務を変える変更は、機械的変更の条件を満たしません。
4. 有効な instruction discovery の証拠を再利用し、入力が変わった場合や証拠が不足する場合、以下の影響するチェックを繰り返します。グローバルの既定方針の更新は、別に比較・統合します。リポジトリのポリシー更新は、グローバル指示の置き換えを必要としません。

## タスク記録の例

実行ポリシーの最小限の記録要件を、既存の issue、PR、タスク、レビュー成果物で満たします。以下はテンプレートであり、レビューや検証を行った証拠ではありません。

```text
レビュー対象: 変更単位または重要な判断成果、目的、作業状態
受入基準または判断基準: 必要な結果と、該当する維持要件
レビューした入力・出力: ソースの識別子と、該当する関連未 commit 差分
plan review: reviewer と判断、または省略理由と result review による確認。実装を伴わない判断だけの場合は該当なし
検証: 範囲、コマンドまたはチェック、実施状態、結果、証拠
result review または decision review: reviewer と判断、または不足する証拠を示した保留
未解決の指摘: 影響する要件、対応状態、残作業
部分作業: 保持した変更と、未完了の agent、コマンド、リソース
判断: pending required review、受入、またはレビュー済みの却下・延期
```

該当する項目だけを使います。このテンプレートは、別の記入用紙を要求するものではありません。適した既存成果物がなければ、簡潔なレビュー応答を記録にできます。実施して成功、実施して失敗、未実施、利用不可を区別します。レビューした差分、または判断成果とその入力への安定した参照を記録します。commit が全状態を特定できない場合は、既存成果物にそれらを保存します。secret と機密情報を記録に含めません。保留レビューの報告は未達条件を示すものであり、受入、却下、延期を確定しません。turn の終了はタスクを完了せず、自動的な background 実行も意味しません。

## 指示の探索と確認

これらの配布元ファイル名は、標準の自動読み込み対象の名前ではありません。Codex は、グローバルの `AGENTS.override.md` または `AGENTS.md` を探索し、次にプロジェクトルートから現在の作業ディレクトリまでのパス上のプロジェクト指示を探索します。各ディレクトリでは、`AGENTS.override.md`、`AGENTS.md`、設定した fallback 名の順に確認し、最大一つの指示ファイルを取り込みます。二つの配布元ファイル名を fallback に登録しても、連結はされません。override は同じ適用範囲の通常ファイルを置き換えるため、必須のポリシー参照と要件を維持することを確認します。[公式の指示探索ドキュメント](https://learn.chatgpt.com/docs/agent-configuration/agents-md) を参照してください。

リンク先の実行ポリシーは、リポジトリのテンプレートが明示的に読み取りを要求するため、読み込まれます。ポリシー文書は、二つ目の自動探索対象の指示ファイルではありません。有効なリポジトリ指示に必須参照を残します。

初回導入では、以下のチェックを使い、実際のファイルと runtime 設定に照らしてセットアップを確認します。更新時は、影響するチェックだけを繰り返します。指示のパス、Codex home、リポジトリルートまたは作業ディレクトリ、override、fallback 名、runtime の能力や上位の制限の変更は、探索の証拠を無効にする場合があります。指示の内容を変えた場合、配置済みの差分と影響する要件の確認が必要です。それだけでは、変わっていない探索パスの証拠は無効になりません。必須の runtime チェックは新しいセッションで行います。更新の受入基準に変更後の振る舞いが含まれる場合、その振る舞いの確認も含めます。

- 意図する Codex home、リポジトリルート、作業ディレクトリ、配置済みの指示ファイルを確認します。別のファイルを選択し得る、同じ適用範囲の override と設定済み fallback 名を確認します。
- リポジトリルートからポリシーリンクを解決し、配置済み文書を確認します。意図するテンプレートとポリシーのペアに属することと、階層下の指示が採用済みのレビュー要件を維持することを確認します。
- 対象リポジトリで新しいセッションを開始します。実際に読んだ絶対パスを特定し、plan review、result review、reviewer の独立性、重要な判断のレビュー、選択済み変更単位の却下・延期のレビュー、レビューを利用できない場合の保留を要約するよう依頼します。自己申告だけを自動読み込みの十分な証拠とせず、配置済みファイルと設定に照らして回答を比較します。
- runtime が指示元の表示や探索ログを提供する場合、追加の証拠として使います。採用を検証済みと扱う前に、不一致を解消します。読み込みを独立して確認できない場合、その制限を報告します。

セットアップ記録では、配置済みファイルの確認、セッションの自己申告、利用可能な探索の証拠、読み取り専用の reviewer 試行を区別します。未実施の runtime チェックを、成功したと報告しません。
